# Пояснение к диаграммам.

--------------------------------------------------------
## Выдача и проверки


вся логика и проверки находятся в s `src/application/services/service_license.py`,
но вот работа с базой данной находится в `src/infra/repositories/license.py`
это нужно чтобы нельзя было пропустить обязательные проверки.
при создании лицензия проходит проверки:

1. проверка существования пользователя
2. проверка возраста покупателя, нельзя выдавать лицензию не совершеннолетнему
3. проверка лимита до 3 лицензий в день включительно
4. проверка что у покупателя нет других действующих лицензий выше или того же ранга

## как считается дневной лимит

при создании создаётся переменная `start_day` с `datetime`, чтобы получить сегодняшнюю дату.
чтобы не потерять те которые были созданы до, с помощью `.replace` сводит минуты, секунды, часы, микросекунды к 0
дальше создаётся `end_day` которому с помощью `relativedelta` к нему добавляется 1 день.
С помощью них создаётся период действия.
далее в репозитории идет поиск лицензий, где `License.issued_at >= start_day,
                                                    License.issued_at < end_day`
ищут лицензии созданные сегодня. Далее через `if >=3` раизется ошибка `DAILY_LIMIT_REACHED`
если лимит превышен

## как обнаруживается истечение
в репозитории лицензии сделан метод `check_execute(self, day: date)`, который принимает сегодняшнюю дату
он ищет лицензии и которых статус активен или приостановлен, а так же те, у которых `.valid_until < 
заменяя статус найденой лицензии EXPIRED. В сервисах этот метод вызывается во всех методах связанных с лицензиями

## где живут проверки в коде

каждый тип проверки лежит в своём слое. Валидация входных данных лежит на `schemas`, проверка ключей, полей в `models`,
работа с запросами в бд лежит в `repositories`, основная бизнес логика находится в сервисах. Роутеры отвечает за
правильные запросы
